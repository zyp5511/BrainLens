# Native vendor recording formats

BrainLens reads clinical vendor EEG/iEEG recordings directly without requiring prior EDF conversion, alongside its existing support for EDF/EDF+C (`.edf`), BDF/BDF+ (`.bdf`), BrainVision (`.vhdr` + `.vmrk` + `.eeg`), FIFF (`.fif` / `.fif.gz`) and BIDS folders.

All newly supported formats open lazily (`preload=False`), bind every companion file (size + SHA-256) through `RecordingSpec.companion_files` for tamper detection and private snapshot staging, reuse BrainLens's existing channel-type inference (SEEG/ECoG/EEG plus sidecar/BIDS overrides) and voltage-unit verification (`unverified_units` skip guard), import vendor events as navigable markers, and mask identifying header fields in MCP responses and de-identified exports.

## Optional extra: Micromed `.TRC`

Micromed SystemPlus `.TRC` support is provided via the optional BSD-3-Clause [`neo`](https://pypi.org/project/neo/) (`python-neo`) package so the core BrainLens install remains lightweight:

```bash
pip install "brainlens[micromed]"
```

With the extra installed, `.TRC`/`.trc` recordings are discovered automatically in folders, read lazily in chunks without preloading the full recording into memory, scaled to volts (`nV`/`uV`/`mV`/`V` verified; non-volt channels marked unverified and skipped by HFO detection), and have their Micromed triggers, notes, and epochs (`Event A`/`Event B`) imported as navigable markers.

## Unsupported formats and recommended workflows

### EGI NetStation (`.mff`)

EGI `.mff` recordings are directory bundles rather than single primary files and require the optional `mffpy` package in MNE 1.13. Because directory-tree integrity does not fit BrainLens's single-file + flat companion verification model cleanly (and `mffpy` is not a core dependency), BrainLens refuses `.mff` targets with `unsupported_format` and advises exporting **EDF+** from EGI NetStation.

### Natus / XLTEK (`.erd`)

Natus/XLTEK `.erd` files use a proprietary, undocumented compressed binary format and are not supported natively. Export recordings as **EDF+** from **Natus NeuroWorks** before opening them in BrainLens. BrainLens refuses `.erd` inputs with `unsupported_format` pointing to NeuroWorks EDF+ export. Discontinuous **EDF+D** exports (commonly produced by long clinical NeuroWorks archives) are supported in this release through a parallel change.

## Integrity, privacy, and downstream compatibility

- **Companion integrity**: All required and present optional companions are hashed (SHA-256) while copied into a private `0700` staging directory and bound in `RecordingSpec.companion_files`. Modifying, deleting, repointing, or adding an unregistered vendor companion after registration triggers `source_recording_missing` or `source_recording_modified` across both full verification and the interactive reader fast path. Companion error messages preserve real file names unless a file name itself contains an identity term for that recording.
- **Identity policy and safe header errors**: Identifying fields from vendor headers follow the same policy as EDF headers (`deid.py`). Local clinical workspaces preserve non-generic identifiers for provenance and cross-recording same-patient checks, while MCP tool responses scrub all header-derived identity terms per recording and opt-in de-identified exports (`deidentify=True`) redact them across case sheets, MDT slides, BIDS event tables, and annotation exports. Malformed vendor headers fail with a dedicated `vendor_header_unreadable` error that reports only the format and exception type — never raw exception text or header field values.
- **Downstream workflow**: `inspect_case`, `analyze_case` (PyHFO), the multichannel waveform reader, Clinical Triad, case sheets, MDT slides, BIDS event exports, and annotation CSV/JSON exports operate identically on vendor formats. Native lossless digital signal copying in `export_edf_annotations` remains EDF/EDF+C-only (CSV + JSON annotations still export for vendor formats).
